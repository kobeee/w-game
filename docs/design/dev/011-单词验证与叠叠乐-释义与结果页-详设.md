## 3. 设计目标与技术约束
- 语言与结构
  - 释义统一为“简体中文”，长度建议 ≤ 20 汉字（如需可调整为 ≤ 25）
  - 响应仅为 JSON 对象，严禁 Markdown、代码块、自然语言头尾
  - JSON Schema 固定为：
    - `{"valid": boolean, "definition": string}`
- 词库质量（对四个 JSON 的硬性要求）
  - Key 大写（A-Z），不含非字母字符
  - `words_*.json`：`by_len` 为对象，键为长度（字符串），值为不重复的数组
  - `zh_gloss*.json`：Key 必须是对应词库存在的单词；Value 必须是简体中文的简明释义（不含英文/拼音/emoji/多余标点）
  - 覆盖率：core 与 extended 均为 100% 覆盖（每个词均有中文释义）
- 性能与鲁棒性
  - 会话内缓存命中尽量减少重复调用
  - 对模型输出解析的容错，但最终 UI 只接收结构化 JSON

## 4. AI 验证接口与提示词规范（面向实现的规格，不写代码）
- 请求入口
  - `POST https://<worker-domain>/gemini/generate`（由 Cloudflare Worker 注入 API Key 并转发官方 `:generateContent`）
- 请求体（关键字段）
  - `contents[].parts[].text`：提示词（Prompt），要求：
    - 语言：中文
    - 行为：判断是否为有效英语单词（包含俚语、专有名词）
    - 输出：必须返回严格 JSON，字段与类型固定
    - 释义：若有效，以简体中文输出简明释义，长度建议 ≤ 20 汉字；无则空字符串
  - `generationConfig`：
    - `temperature: 0.0`
    - `maxOutputTokens: 32`（可根据实际稳定性微调至 64）
    - `candidateCount: 1`
    - `response_mime_type: "application/json"`
    - `response_schema`：
      - `type: "OBJECT"`
      - `properties.valid: BOOLEAN`
      - `properties.definition: STRING`
      - `required: ["valid", "definition"]`
- 解析与容错（仅规格）
  - 优先解析 `candidates[0].content.parts[0].text` 为 JSON
  - 若存在直接对象（少见）且符合 schema，可直接使用
  - 解析失败：返回 `valid=false, definition=""`（同时走本地词库回退路径）
- 错误处理规范
  - 超时（≤5s）：按失败处理，不阻塞 UI，允许本地结果先行
  - 非 2xx：按失败处理；记录错误类型用于上报（后续可统计）

## 6. 叠叠乐：释义提示气泡 UI 设计与 Cocos Creator 3.8.7 操作步骤
说明：以下步骤严格基于 Cocos Creator 3.8.7 编辑器（Hierarchy/Inspector/Assets）实际操作路径撰写，术语与面板命名与 3.8.7 保持一致。涉及脚本属性绑定时，仅做“拖拽绑定”的指引，不提供实现代码。

### 6.1 新建释义提示气泡 Prefab（DefinitionHint）
1) 在 Assets 视图中创建目录：`assets/resources/ui/definitions/`
2) 在该目录空白处右键 → Create → Prefab，命名：`DefinitionHint.prefab`
3) 双击打开 Prefab，根节点命名为 `DefinitionHint`
4) 选中 `DefinitionHint`（根节点）在 Inspector：
   - 确认已有 `UITransform` 组件，`Content Size` 设为 `320 x 80`
   - 添加组件 `Widget`，保持四边未勾选（定位由脚本控制）
   - 添加组件 `UIOpacity`（若需要淡入淡出动画时使用），默认不修改
5) 在 `DefinitionHint` 下创建子节点 `Bg`：
   - 添加 `Sprite` 组件：`Type = Sliced`，`SpriteFrame` 选择项目内通用 9 切片面板（无则临时用纯色）
   - `Color = #111111` 且 `A ≈ 200`
   - `UITransform.Content Size = 320 x 80`
6) 在 `DefinitionHint` 下创建子节点 `Text`：
   - 添加 `Label` 组件：
     - `String = WORD · 中文释义`（占位）
     - `Horizontal Align = CENTER`，`Vertical Align = CENTER`
     - `Overflow = SHRINK`（自动收缩）
     - `Font Size = 24`，`Line Height = 28`，`Color = #FFFFFF`
   - `UITransform.Content Size = 300 x 56`，`Anchor = (0.5, 0.5)`，`Position = (0, 0, 0)`
7) 菜单 File → Save（或 Ctrl/Cmd + S）保存 Prefab

### 6.2 在叠叠乐场景中放置容器节点（DefinitionHints 容器）
1) 打开 `StackGameScene.scene`
2) 在 `Canvas` 下右键 → Create → Empty Node，命名：`DefinitionHints`
3) 选中 `DefinitionHints` 在 Inspector：
   - 确认 `UITransform` 存在（Canvas 子节点会自动带有），保持与 `Canvas` 同大小（一般无需手动改）
   - 添加组件 `Widget`，勾选 `Top/Bottom/Left/Right`（四边对齐到父节点）
   - 保持 `Anchor = (0.5, 0.5)`，`Position = (0, 0, 0)`
4) 层级要求：`DefinitionHints` 节点在棋盘节点之上、在结果面板之下（见 7.2）
5) 用途：承载运行时实例化的 `DefinitionHint`，脚本将负责定位/淡入/淡出/回收

### 6.3 资源绑定（待代码暴露属性后执行）
1) 选中场景中绑定 `StackGameApp` 的节点（通常是 `Canvas` 或主控制器节点）
2) 在 Inspector 的 `StackGameApp` 组件中，找到以下属性（待脚本暴露）：
   - `definitionHintPrefab: Prefab`
   - `definitionHintsRoot: Node`
3) 从 Assets 将 `DefinitionHint.prefab` 拖拽到 `definitionHintPrefab`
4) 从 Hierarchy 将 `DefinitionHints` 节点拖拽到 `definitionHintsRoot`
5) File → Save Scene 保存

### 6.4 UI 行为规范（面向实现的规格）
- 入场：在单词消除位置上方偏移 `+40~+64 px` 显示，0.1s 淡入
- 停留：1.2~1.6s
- 退场：0.2s 向上位移 `+20 px` 并淡出至 0，然后归还对象池
- 并发：同一时刻最多显示 3 个，多余请求进入 1 秒内的短队列；若仍堆积，丢弃最老未显示项（避免 UI 拥塞）
- 文案优先级：本地释义 > AI 释义 > “无释义（扩展词库）”

## 7. 叠叠乐：结果页 UI 设计与 Cocos Creator 3.8.7 操作步骤
说明：仅通过编辑器完成层级与组件配置；按钮回调通过 Inspector 的 Button「Click Events」完成 Node→Component→Handler 的 1→2→3 顺序绑定（与官方示例一致）。

### 7.1 新建结果页 Panel（ResultPanel）
1) 在 `Canvas` 下右键 → Create → Empty Node，命名：`ResultPanel`
2) 选中 `ResultPanel` 在 Inspector：
   - `Active = false`（默认隐藏）
   - 确认 `UITransform` 存在
   - 添加 `Widget`，勾选 `Top/Bottom/Left/Right`（全屏铺满）
   - 添加组件 `BlockInputEvents`（防穿透）
3) 在 `ResultPanel` 下创建子节点 `Mask`：
   - 添加 `Sprite`，`Color = #000000`，`Opacity ≈ 160~200`
   - 添加 `Widget`，勾选四边（全屏遮罩）
4) 在 `ResultPanel` 下创建子节点 `Content`（面板容器）：
   - 添加 `Sprite`：`Type = Sliced`，选通用面板底图（或纯色）
   - `UITransform.Content Size = 720 x 920`（示例）
   - 添加 `Widget`：`Align` 水平/垂直居中（勾选 `Horizontal Center` 与 `Vertical Center`）
5) 在 `Content` 下创建标题 `Title`：
   - 添加 `Label`：`String = 本局结果`，`Font Size = 36`，`Bold = On`
   - `UITransform.Content Size = 680 x 60`，`Position ≈ (0, 400, 0)`
6) 在 `Content` 下创建统计区 `Stats`：
   - 创建 3 个 `Label` 子节点：`ScoreLabel`、`TimeLabel`、`WordsLabel`
     - 初始字符串分别示例：`得分：0000` / `用时：00:00` / `清除词数：0`
     - `Font Size = 28`，`Line Height = 32`
   - 可选：给 `Stats` 添加 `Layout`（Vertical），`Spacing = 12`，便于垂直排列
7) 在 `Content` 下创建滚动列表：
   - 右键 → UI → ScrollView，命名：`WordsScrollView`
   - 选中 `WordsScrollView`：
     - `UITransform.Content Size = 680 x 520`
     - 勾选 `Inertia`；`Vertical` 模式（默认）
     - 其子节点 `View` 默认带 `Mask`，其下 `Content` 节点作为动态项的父节点
   - 选中 `WordsScrollView/View/Content`：
     - 添加 `Layout`：`Type = Vertical`，`Padding(上右下左) = 8`，`Spacing = 6`
8) 在 `Content` 下创建按钮区 `Buttons`：
   - 添加 `Layout: Horizontal`，`Spacing = 24`，`Resize Mode = Container`（可选）
   - 在 `Buttons` 下创建两个 UI → Button：`RetryButton`、`BackButton`
     - 进入各按钮下的 `Label` 子节点，修改显示文字为“再来一局”“返回主页”
     - Button 的 `Transition` 选择 `SCALE` 或 `COLOR`，`Duration ≈ 0.08`
   - 将 `Buttons` 放在面板底部（如 `Position ≈ (0, -380, 0)`）

### 13.2 NetworkService 设计（`src/cocos/assets/scripts/services/NetworkService.ts`）
- 职责：封装直连 Cloudflare Worker 的 Gemini 调用；提供会话级缓存与“单飞”并发合并。
- 公开静态方法
  - `validateWord(word: string): Promise<{ valid: boolean; definition?: string; source: 'cache' | 'gemini' } | null>`
    - 行为：先查会话缓存 → 命中则返回 `source='cache'`；否则发起 `callGeminiValidate` → 写入缓存 → 返回 `source='gemini'`；失败返回 `null`
  - `clearWordCache(): void`
    - 行为：清空会话缓存 Map
- 内部静态方法（对外不可见，但签名固定便于测试）
  - `callGeminiValidate(wordUpper: string): Promise<{ valid: boolean; definition?: string }>`
    - 请求体：提示词使用中文，强制 JSON Schema（定义见 4 章）；`temperature=0.0`、`maxOutputTokens=32~64`、`response_mime_type=application/json`、`response_schema` 同步
    - 解析：优先 `candidates[0].content.parts[0].text`；解析失败返回 `{ valid:false, definition:'' }`
  - `extractTextFromGemini(resp: any): string`
  - `tryParseJson(s: string): any | null`
- 错误/超时约定
  - 超时或网络错误：`validateWord` 返回 `null`，上层自行决定回退
- 缓存与并发
  - `wordCache: Map<string, { value: { valid: boolean; definition?: string; source: 'cache' | 'gemini' }, expireAt: number }>`
  - `inflight: Map<string, Promise<...>>`
  - 相同大写单词在有效期内共用结果；相同单词并发请求共用同一个 Promise

### 13.3 LocalDictionary 设计（`src/cocos/assets/scripts/services/LocalDictionary.ts`）
- 职责：加载核心与扩展词库、合并中文释义映射，提供 O(1) 查询
- 公开方法
  - `async load(): Promise<void>`：一次性加载并合并四文件（核心/扩展词条与释义）；允许幂等
  - `get(word: string): { valid: boolean; definition?: string }`
    - 逻辑：优先核心映射（有释义）→ 再查扩展词（若扩展映射存在释义也应返回）→ 不存在则 `valid=false`
  - `isReady(): boolean`
- 数据结构
  - `coreDict: Map<string, string>`：核心+扩展映射统一合入（仅中文释义）
  - `extendedSet: Set<string>`：扩展词存在性判定（若释义缺失时返回 `valid=true` 且 `definition=undefined`，但按本次交付会 100% 完整）

### 13.4 HybridWordValidator 设计（`src/cocos/assets/scripts/services/HybridWordValidator.ts`）
- 职责：三层校验编排（本地 → 网络 → 容错）
- 公开方法
  - `async initialize(): Promise<void>`：懒加载 LocalDictionary
  - `async validate(word: string): Promise<ValidateResult>`
    - 流程：
      1) 词统一大写，记录 `startTime`
      2) 本地查询：若 `valid=true`，返回 `{ valid:true, definition:中文释义, source:'local', latency }`
      3) 网络查询：调用 `NetworkService.validateWord`，若返回 `{ valid:true }` 则 `{ source:'gemini' }`；若 `null` 则进入容错
      4) 容错：返回 `{ valid:false, source:'offline' }`
    - 任何异常均捕获并转换为 `ValidateResult`（含 `error` 与 `latency`）

### 13.5 WordValidationManager 设计（`src/cocos/assets/scripts/services/WordValidationManager.ts`）
- 职责：对外提供“与动画并发”的验证接口、同词去抖与状态缓存；向上层回调结果
- 公开方法
  - `async initialize(): Promise<void>`：初始化内部 `HybridWordValidator`
  - `async validateConcurrent(word: string): Promise<ValidateResult>`：按现有去抖/并发约束执行，完成即返回结果
  - `setOnValidationFinished(cb: (word: string, result: ValidateResult) => void): void`（新增）
    - 用于 `StackGameApp` 订阅验证完成事件（若已有事件总线可替换）
- 内部状态
  - `timersByWord: Map<string, any>`、`pendingsByWord: Map<string, PendingValidation>`
  - `currentAbort: AbortController | null`（保留以便未来扩展取消）

### 13.6 DefinitionHint 视图脚本设计（`src/cocos/assets/scripts/ui/DefinitionHintView.ts`，新增）

- 行为契约
  - 文案过长时 Label 收缩（溢出 SHRINK 已在 Prefab 设定）
  - 主动调用 `dismiss` 或超时自动销毁（由上层池管理调用）

### 13.7 气泡对象池设计（`src/cocos/assets/scripts/ui/DefinitionHintPool.ts`，新增）
- 职责：复用 `DefinitionHint.prefab` 实例，限制并发展示数量

## 16. 计分与结束判定（公式与触发契约）
### 16.1 计分公式（如需调整仅改常量）
- 记分规则（示例，避免歧义，按此实现）：
  - 基础分 = `单词长度 × 10`
  - 额外分（可选，v1 关闭）：连消或稀有词奖励 = 0
  - 本期总分计算：`scoreDelta = length(word) * 10`
- 记录：
  - `wordsCleared.push({ word, valid: true, scoreDelta, definition, clearedAtMs: now })`
  - `longestWordLen = max(longestWordLen, word.length)`
  - `score += scoreDelta`

### 16.2 结束判定（三类触发之一）
- `SLOTS_FILLED`：棋盘/槽位系统回调触发（当下方槽位满且无可行移动）
- `NO_TILES`：牌堆/可点字母耗尽回调触发
- `MANUAL`：玩家点击“结束”按钮触发（如场景已有）
- 任一触发时：
  - `const durationMs = now - startTime`
  - 聚合 `GameResult` 并调用 `openResultPanel(result)`
