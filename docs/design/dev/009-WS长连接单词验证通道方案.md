### 目标
- 将“单词校验”改为首选 WebSocket 长连接通道，显著降低端到端时延与抖动；连接失败自动回退 REST；保留现有安全与缓存体系，尽量少改、快速落地。

### 拓扑与通道
- 客户端（小游戏/浏览器）⇄ Cloudflare Worker（WS 直通，轻量限流+统计）⇄ FastAPI WebSocket（/ws/word）
- 失败自动回退：WS 建联失败或中断 → 立即改用现有 REST `/api/v1/word/verify`（保留现有加密转发链路）。

### 安全（Phase 1，简洁可用）
- 边缘到后端：使用共享边缘令牌 `X-Edge-Token: <EDGE_SHARED_TOKEN>`（Worker 注入，请求头传入；后端环境变量校验）。
- 客户端到边缘：走 HTTPS + Cloudflare；不再对每条消息做 RSA，避免额外开销。
- 注：后续如需加强，可在 Phase 2 引入“握手一次性 token”或 ECDH→AES 会话密钥。

### 连接管理（控制连接数与生命周期）
- 每客户端仅 1 条活跃 WS：Worker 侧用内存 Map 维护 `clientId → connId`，新建即踢掉旧的（简单直接）。
- IP 级上限：每个 IP（或 `CF-Connecting-IP`）最多 3–5 条连接；超限拒绝并返回 `notice.rate_limit`。
- 旋转重置：server 在 90s 发送 `notice.rotate` 并优雅关闭（code=4000）→ 客户端立即重连（带 jitter）。
- 空闲超时：45s 没有上下行即 server 主动关闭（code=4001）；客户端收到后立刻重连。
- 心跳：15–30s `ping/pong`；3 次未收到 `pong` 判定断线，走重连。

### 消息协议（紧凑）
- 客户端 → 服务端
  - hello { clientId, scene: 'stack', ts }
  - validate { rid, word } 仅发送 >=3 且“当前最长前缀”（配合 150ms 防抖）
  - ping {}
- 服务端 → 客户端
  - hello-ack { sessionId, heartbeatSec: 20, rotateSec: 90, rateLimit?: { maxConnPerIp } }
  - validate-res { rid, word, valid, definition?, source: 'cache'|'gemini', latencyMs, cache: boolean }
  - notice { type: 'rate_limit'|'rotate'|'closing', detail? }
  - pong {}

示例（validate / validate-res）

```json
// client → server
{ "type": "validate", "rid": "b3f2", "word": "ARROW" }

// server → client
{ "type": "validate-res", "rid": "b3f2", "word": "ARROW", "valid": true, "definition": "箭", "source": "cache", "latencyMs": 86, "cache": true }
```

### 端到端流程（简述）
1) 客户端进入叠叠乐场景 → 立刻尝试 WS 建联；失败则记录关键日志后回退 REST（并定时背景重试 WS）。
2) 输入过程中（加字母）：150ms 防抖，仅发送“当前最长前缀”的 `validate`；上一条未完成时直接以“最后一次”为准。
3) 服务端收到 `validate`：
   - 命中进程 LRU 或 Redis → 直接返回（source=cache）。
   - MISS → SingleFlight 外呼 Gemini → 返回并写入缓存。
4) 每 20s 心跳；90s 通知 rotate 并重连；45s idle 断开并重连。

### 回退策略（必须）
- 建联失败：
  - 记录：ws_connect_failed { reason, dnsMs?, tlsMs?, totalMs, try=n }
  - 立即切 REST；后台指数退避+jitter 重试 WS（例如 1s/2s/4s… 最大 30s）。
- 建联成功但消息失败：
  - 单次 `validate` 超时 2.5s：记录并临时改用 REST 处理当前词，WS 连接继续保留。

### 指标与日志（最小集合，便于核算提效）
- 连接级：sessionId, clientId, startTs, closeTs, closeCode, bytesIn/Out, pingLossCount。
- 请求级：rid, word, t0→tDone(ms), source(cache|gemini), cache(true|false), ws(true|false|fallback_rest), edgeCache(X-Edge-Cache)。
- 统计：p50/p95/p99（WS 与 REST 分开）；错误分布（connect、timeout、http、parse）。

### 限流与背压（简单有效）
- Worker：`clientId` 单连接；每 IP ≤ 5；超限拒绝。
- 服务端：每连接“仅允许 1 个并发验证”，新请求到达时取消上一个（只保留最后一次）。
- 队列长度=0，不排队，避免堆积放大延迟。

### 客户端配合（已具备/需补充）
- 已有：150ms 防抖、会话内缓存、单飞去重、REST 容错。
- 需补：WS 优先策略、失败回退 REST、后台重试建联、对 `notice.rotate/closing` 的重连处理、对 `validate-res.latencyMs` 打点显示。

### 实施范围（Phase 1）
- Worker：新增 WS 直通与轻量限流、注入 `X-Edge-Token`；保留 REST 代理。
- 后端：新增 `/ws/word`（FastAPI WebSocket），复用现有缓存/SingleFlight/Gemini 客户端。
- 客户端：优先 WS（建联失败自动回退 REST），保持现有 REST 逻辑不变。

### 风险与回退
- 风险：边缘实例漂移导致少量连接中断（通过 90s rotate 与心跳快速自愈）。
- 回退：任意阶段、任意错误 → 立即回退 REST；开关可由灰度配置控制（例如 client 配置项）。

### 性能预估（端到端）
- 首次 MISS（走 Gemini）：
  - WS：300–650ms（p50），650–850ms（p95）
  - REST（回退路径）：350–900ms（p50~p95）
- 命中缓存（边缘/后端/会话）：
  - WS：60–120ms（p50），100–180ms（p95）
  - REST：80–180ms（p50），150–280ms（p95）
- 快速连点不同词：因 150ms 防抖与“只发最后一次”，平均显著下降，2s 超时基本消失。

### 验收要点
- 建联失败自动回退 REST（有关键日志）；
- validate-res 都含 `latencyMs` 与 `cache` 字段；
- 重复词第二次起明显 < 120ms；
- 90s 轮转不影响可玩性；
- p95 明显优于现状（目标 < 650–850ms）。

## 详细设计（开发可直接落地）

### 一、配置清单（默认值）
- 环境变量（后端）：
  - `EDGE_SHARED_TOKEN`：边缘到后端共享令牌（必填）。
  - `WS_HEARTBEAT_SEC=20`：心跳间隔；`WS_ROTATE_SEC=90`：旋转间隔；`WS_IDLE_SEC=45`：空闲超时。
  - `WS_MAX_CONN_PER_IP=5`：每 IP 最大连接数（Worker 实施，后端兜底）。
- Worker 常量：
  - `EDGE_CACHE_TTL_MS=3600_000`（已有）；`MAX_CONN_PER_IP=5`；`SINGLE_CONN_PER_CLIENT=true`。

### 二、消息协议（严格 JSON Schema）
- 通用信封：
  - `type: "hello" | "hello-ack" | "validate" | "validate-res" | "ping" | "pong" | "notice"`
- 客户端 → 服务端
  - hello: `{ "type":"hello", "clientId": string, "scene":"stack", "ts": number }`
  - validate: `{ "type":"validate", "rid": string, "word": string }`（`word` 大写，len>=3）
  - ping: `{ "type":"ping" }`
- 服务端 → 客户端
  - hello-ack: `{ "type":"hello-ack", "sessionId": string, "heartbeatSec": number, "rotateSec": number, "rateLimit": { "maxConnPerIp": number } }`
  - validate-res: `{ "type":"validate-res", "rid": string, "word": string, "valid": boolean, "definition"?: string, "source": "cache"|"gemini", "latencyMs": number, "cache": boolean }`
  - pong: `{ "type":"pong" }`
  - notice: `{ "type":"notice", "noticeType": "rate_limit"|"rotate"|"closing", "detail"?: string }`

错误码（仅日志用）：`WS_CONN_FAIL`、`WS_MSG_PARSE_ERR`、`WS_VALIDATE_TIMEOUT`、`EDGE_RATE_LIMIT`、`BACKEND_RATE_LIMIT`。

### 三、连接状态机（文本版）
- `DISCONNECTED` → connect() → `CONNECTING`
- `CONNECTING`
  - success → send hello → wait ack → `CONNECTED`
  - fail → `FALLBACK_REST` + schedule retry（1s/2s/4s… ≤30s）→ `DISCONNECTED`
- `CONNECTED`
  - 每 15–30s 发送 ping；收到 pong → 继续
  - 超过 3 次 ping 无 pong → `DISCONNECTED`（记录）
  - 收到 notice.rotate → 立即重连（无缝切换）
  - idle>45s → 服务端主动关闭 → 立即重连

### 四、时序（文字版）
1) 进入场景 t=0：客户端尝试 WS 建联；并行加载资源。
2) t=+10~100ms：握手成功 → hello/ack；开始心跳与 rotate 定时器。
3) 输入变更：150ms 防抖后发 `validate`（若有未决，直接以最后一次为准）。
4) 服务端：查 LRU/Redis → 命中返回，MISS 则 SingleFlight 外呼 Gemini → 返回；写入缓存。
5) 90s：服务端发 notice.rotate，客户端立即重连；过程内短暂停顿不影响体验。

### 五、Cloudflare Worker（WS 直通，伪代码）
```js
// 仅示意核心逻辑
async function handleWs(request) {
  const url = new URL(request.url);
  if (url.pathname !== '/w-game-service/ws/word') return new Response('404', { status: 404 });

  // 限流：clientId 单连接；每 IP ≤ MAX_CONN_PER_IP
  const cfIp = request.headers.get('CF-Connecting-IP');
  const clientId = url.searchParams.get('clientId') || '';
  if (!allowNewConnection(cfIp, clientId)) {
    return new Response('Too Many Connections', { status: 429 });
  }

  const pair = new WebSocketPair();
  const [client, server] = Object.values(pair);
  server.accept();

  // 建链时向后端发起 WebSocket 直连（保持同一 TCP/TLS lifo）
  const upstream = await fetch('http://elvis1949.top:9100/ws/word', {
    headers: { 'X-Edge-Token': EDGE_SHARED_TOKEN, 'CF-Connecting-IP': cfIp },
    method: 'GET',
    duplex: 'half',
    webSocket: server,
  });

  return new Response(null, { status: 101, webSocket: client });
}
```

注意：
- 生产中可在 Worker 仅做直通+限流；日志计数（连接数、失败原因）。
- 边缘 LRU 结果缓存继续用于 REST 路径；WS 路径首期不做边缘缓存（简化）。

### 六、后端 FastAPI WebSocket（伪代码）
```python
@app.websocket('/ws/word')
async def ws_word(websocket: WebSocket):
    # 安全校验
    if websocket.headers.get('X-Edge-Token') != EDGE_SHARED_TOKEN:
        await websocket.close(code=4401)
        return
    await websocket.accept()

    session_id = gen_session_id()
    start_t = now_ms()
    last_active = start_t

    # 连接级定时器：心跳检查/旋转/空闲
    hb = create_task(heartbeat(websocket))   # 每 heartbeatSec 发送 pong
    rot = create_task(rotate_after(websocket, rotateSec=90))
    idle = create_task(idle_close_if_no_activity(websocket, idleSec=45))

    # 单飞去重 / 进程内 LRU/Redis 已复用现有实现
    try:
        await websocket.send_json({ 'type':'hello-ack', 'sessionId': session_id, 'heartbeatSec': 20, 'rotateSec': 90, 'rateLimit': { 'maxConnPerIp': WS_MAX_CONN_PER_IP } })
        while True:
            msg = await websocket.receive_json()
            last_active = now_ms()
            if msg.get('type') == 'ping':
                await websocket.send_json({ 'type':'pong' })
            elif msg.get('type') == 'validate':
                rid, word = msg.get('rid'), (msg.get('word') or '').upper()
                t0 = now_ms()
                # 仅保留最后一次：若有未决则取消
                cancel_previous_if_any(session_id)
                result = await validate_word_service(word)  # 复用现有 LRU/Redis/Gemini
                latency = now_ms() - t0
                await websocket.send_json({ 'type':'validate-res', 'rid': rid, 'word': word, 'valid': result.valid, 'definition': result.definition, 'source': result.source, 'latencyMs': latency, 'cache': (result.source=='cache') })
            else:
                # 非法消息
                continue
    except Exception as e:
        log_ws_error(session_id, e)
    finally:
        for t in [hb, rot, idle]:
            safe_cancel(t)
        await websocket.close(code=1000)
```

### 七、客户端改造（落地点与签名）
- 新增 `WebSocketWordChannel.ts`：
  - `connect(clientId): Promise<void>` 建联（带重试、回退 REST 标志位）；
  - `validate(word, rid): Promise<void>` 发送校验（由 `WordValidationManager` 调用）；
  - 处理 `hello-ack/pong/notice/validate-res`；
  - 公开事件：`onValidateRes({rid, word, valid, definition, source, latencyMs, cache})`；
  - 记录关键日志：`ws_connect_failed`、`ws_rotate`、`ws_idle_close`、`ws_validate_timeout`。
- `WordValidationManager.ts`：
  - 150ms 防抖只发“最后一次”；优先走 WS 通道；WS 不可用时调用现有 `NetworkService.validateWord()`。
- `NetworkService.ts`：保持不变作为回退；会话缓存/单飞已加。

### 八、日志与指标（字段定义与示例）
- 连接级（后端 JSON 行）：
  - `{ ts, level:'info', evt:'ws_connect', sessionId, clientIp, ua?, edge: true, heartbeatSec: 20, rotateSec: 90 }`
  - `{ ts, level:'warn', evt:'ws_connect_failed', reason, totalMs, try }`
  - `{ ts, level:'info', evt:'ws_close', sessionId, code, durMs, bytesIn, bytesOut }`
- 请求级：
  - `{ ts, level:'info', evt:'validate', sessionId, rid, word, source:'cache'|'gemini', latencyMs, cache: true|false, ws:true|false|fallback_rest:true|false }`

### 九、测试用例（最小集合）
1) 建联成功 → hello/ack 正确；心跳、旋转、空闲超时均能触发并自动重连。
2) 建联失败 → 立刻回退 REST；后台指数退避重试；日志包含失败原因与时长。
3) validate 命中缓存 → < 180ms；MISS → < 900ms；响应体含 `latencyMs` 与 `cache`。
4) 快速连点不同词 → 仅最后一次发出；无堆积、无多条并发。
5) IP 超限 → 连接被拒；收到 `notice.rate_limit`。
6) 90s 旋转 → 不中断可玩性；重连后继续正常校验。

- 回滚：任意异常可在客户端关闭 WS 开关，立即仅走 REST。
