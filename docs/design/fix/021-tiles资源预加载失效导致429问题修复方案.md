# 021-tiles资源预加载失效导致429问题修复方案

## 问题现象

进入"小试牛刀"或"叠叠乐"场景后，开始加载tiles资源时**必定出现429错误**。tiles资源共5张图片（selectable、highlight、correct、wrong、disabled），加载过程中重试后通常只能成功4个，偶尔3个，无法全部顺利成功。

## 问题日志

Loading阶段关键日志：

```
[PreloadManager] 🚀 开始启动阶段资源加载（单Bundle版）...
[LoadingUI] 进度: 0% - 正在加载 bundle 资源包...
[PreloadManager.loadSingleBundle] ✅ Bundle 'bundle' 加载完成
[LoadingUI] 进度: 30% - bundle 资源包加载完成
[PreloadManager] Bundle 0.3 未加载，跳过关键资源预加载   ← 🚨 关键问题！
[LoadingUI] 进度: 80% - 正在加载核心词库数据...
```

**注意**：日志显示 `Bundle 0.3 未加载`，而不是 `Bundle bundle 未加载`！

## 根本原因分析

### 1. 方法命名冲突

`PreloadManager.ts` 中存在**两个同名方法** `preloadCriticalAssets`：

```typescript
// L529: 私有方法（用于启动阶段预热关键资源）
private async preloadCriticalAssets(startProgress: number, endProgress: number): Promise<void> {
    // 这个方法会预加载 STARTUP_ASSETS 中的所有资源，包括5个tiles
}

// L712: 公开方法（兼容性方法）
public async preloadCriticalAssets(bundleName: string): Promise<void> {
    const bundle = this.getLoadedBundle(bundleName);
    if (!bundle) {
        console.warn(`[PreloadManager] Bundle ${bundleName} 未加载，跳过关键资源预加载`);
        return;
    }
    // ...
}
```

### 2. JavaScript 方法覆盖机制

TypeScript/JavaScript 类中**不支持方法重载**，当存在同名方法时，后定义的方法会覆盖先定义的方法。

由于公开方法（L712）定义在私有方法（L529）之后，**公开方法覆盖了私有方法**。

### 3. 调用时参数被错误解析

在 `preloadStartupBundles()` 中的调用：

```typescript
// L92
await this.preloadCriticalAssets(0.3, 0.8);  // 意图：传入进度范围
```

实际执行的是 L712 的公开方法：
- 第一个参数 `0.3` 被当作 `bundleName`（JavaScript 自动转换为字符串 `"0.3"`）
- 第二个参数 `0.8` 被忽略

然后 `getLoadedBundle("0.3")` 返回 `null`（因为不存在名为 "0.3" 的 Bundle），导致**整个关键资源预加载被跳过**！

## 问题影响链

```
Loading阶段
    ↓
preloadCriticalAssets(0.3, 0.8) 调用
    ↓
错误执行公开方法，bundleName = "0.3"
    ↓
getLoadedBundle("0.3") 返回 null
    ↓
"Bundle 0.3 未加载，跳过关键资源预加载"
    ↓
STARTUP_ASSETS 中的13个资源全部未预加载（包括5个tiles）
    ↓
进入游戏场景
    ↓
LetterTile.loadTileSprites() 尝试加载5个tiles
    ↓
缓存未命中（因为没有预加载）
    ↓
触发5个网络请求
    ↓
429错误（服务器限流）
```

## 修复方案

### 方案A：重命名私有方法（推荐）

将私有方法重命名为 `preloadCriticalAssetsWithProgress`，避免命名冲突：

```typescript
// L529: 修改前
private async preloadCriticalAssets(startProgress: number, endProgress: number): Promise<void>

// L529: 修改后
private async preloadCriticalAssetsWithProgress(startProgress: number, endProgress: number): Promise<void>
```

同时修改调用处：

```typescript
// L92: 修改前
await this.preloadCriticalAssets(0.3, 0.8);

// L92: 修改后
await this.preloadCriticalAssetsWithProgress(0.3, 0.8);
```

### 方案B：重命名公开方法

将公开方法重命名为 `preloadCriticalAssetsForBundle`：

```typescript
// L712: 修改前
public async preloadCriticalAssets(bundleName: string): Promise<void>

// L712: 修改后
public async preloadCriticalAssetsForBundle(bundleName: string): Promise<void>
```

需要检查是否有外部调用此方法，如有则同步修改。

### 方案C：删除公开方法（如果不再使用）

如果 L712 的公开方法已经没有外部调用，可以直接删除：

```typescript
// 删除 L709-L731 的整个公开方法
```

## 经验教训

1. **避免同名方法**：TypeScript 类中不要定义同名方法，即使参数签名不同
2. **日志诊断价值**：`Bundle 0.3 未加载` 这个异常的日志是定位问题的关键线索
3. **方法重载陷阱**：TypeScript 的方法重载只是编译时检查，运行时 JavaScript 不支持真正的方法重载
