## 一、 为什么之前的方案都会失败？ (The Naked Truth)

在经历了ZIP化、轻量级队列、引擎预设配置（Solution 013）的失败后，我们需要诚实地面对现实。方案013失败的核心原因在于**Cocos引擎的抽象泄漏（Abstraction Leakage）**。

### 1.1 引擎配置的"虚假繁荣"
即使我们设置了 `assetManager.presets['bundle'].maxConcurrency = 2`，依然会触发429，原因如下：

1.  **管辖范围有限**：`preset` 仅控制 `assetManager` 发起的加载。但是，微信小游戏环境中，Cocos底层适配器（Adapter）在某些情况下（如加载脚本、音频、字体或某些特定资源类型）可能会绕过通用下载器，直接调用 `wx` API。
2.  **多管道并发**：Cocos拥有多个管道（Pipe），`Preload` 是一条线，`Scene` 加载是一条线，`Audio` 加载是一条线。虽然引擎试图协调，但在高负载下（Main场景初始化），这些管道可能同时向底层请求资源。`2 + 2 + 2` 很容易就超过了 `10`。
3.  **第三方干扰**：如果在项目中引入了统计SDK、广告SDK，它们发起的 HTTP 请求完全不受 Cocos 引擎控制，直接占用微信的并发配额。

### 1.2 第一性原理再回归
**429错误的唯一判决者是微信客户端**。

微信不关心你是 Cocos 引擎、Laya 引擎，还是原生 JS。微信只看一点：
> **此时此刻，通过 `wx.request` + `wx.downloadFile` + `wx.uploadFile` 创建的 Socket 连接数是否 > 10？**

如果答案是 YES，它就报 429。

因此，**任何试图在 Cocos 逻辑层（应用层或引擎层）解决问题的方案，都是在隔靴搔痒**。只要底层漏掉一个请求，方案就宣告破产。

**唯一的出路**：
我们必须下沉到**最底层**，直接接管 `wx.downloadFile` 和 `wx.request`。建立一个**上帝视角的全局拦截器（Global Interceptor）**。

## 二、 解决方案架构：全局API代理 (Global API Proxy)

### 2.1 核心思路
不修改 Cocos 引擎，不修改业务逻辑。我们在游戏启动的最早期（Cocos 引擎初始化之前），**劫持（Hook）** 微信原生网络 API。

所有的网络请求，必须经过我们的 **"海关"（WXNetworkGate）**。

### 2.2 架构图

```mermaid
    end

    F -->|Complete| D
    D -->|Next| Q
```

### 2.3 关键设计决策

1.  **安全阈值 (Safe Threshold) = 6**
    *   微信官方限制是 10。
    *   我们将代理池限制为 **6**。
    *   **预留 4 个名额** 给：
        *   `wx.uploadFile`（通常用于日志上报，我们不拦截上传，避免阻塞关键日志）。
        *   `wx.connectSocket`（WebSocket 不共享 HTTP 并发，但在底层 Socket 层面即使分开，保留余量更安全）。
        *   **未被拦截的系统级请求**（如微信自身的某些回调）。
    
2.  **代理对象 (Proxy Object)**
    *   `wx.downloadFile` 返回 `DownloadTask`对象（具有 `.abort()` 等方法）。
    *   我们的代理必须返回一个 **"虚拟 Task"**。当请求在排队时，调用虚拟 Task 的 `.abort()` 必须能从队列中移除该请求；当请求实际发出后，必须桥接到真实的 Task。

3.  **注入时机**
    *   必须在 `require('cocos-js')` 之前。
    *   最佳位置：`game.js` 的最顶部，或者构建模板的 `game.ejs`。

## 三、 实施方案 (Implementation)

该方案由一个独立的 TypeScript/JavaScript 文件组成，编译后作为插件或直接注入 `game.js`。

### 3.1 代码实现：`WXNetworkGate.js`

请在 `build-templates/wechatgame/` 下（或手动在构建后的 `wechatgame/` 目录）创建该逻辑。建议在项目 `src` 下维护，构建时注入。

```javascript
/**
 * WXNetworkGate.js
 * 究极429解决方案 - 底层API拦截器
 * 
 * 功能：劫持 wx.request 和 wx.downloadFile，实现全局并发控制
 * 兼容性：完全兼容 wx 原生接口定义
 */

(function() {
    // 🛡️ 防御性检查
    if (typeof wx === 'undefined') return;
    if (wx.__network_gate_installed__) return;

    console.log('[WXGate] 正在初始化全局网络拦截器...');

    // ================= 配置区 =================
    const MAX_CONCURRENCY = 6; // 最大并发数 (保守值)
    const RETRY_COUNT = 3;     // 429重试次数
    const RETRY_DELAY = 1000;  // 重试延迟(ms)
    // =========================================

    // 原始方法备份
    const _originalRequest = wx.request;
    const _originalDownload = wx.downloadFile;

    // 状态管理
    let _runningCount = 0;
    const _queue = [];

    /**
     * 核心调度器
     */
    function _scheduler() {
        if (_runningCount >= MAX_CONCURRENCY) return;
        if (_queue.length === 0) return;

        // 取出下一个任务
        const taskParams = _queue.shift();
        
        // 如果任务已被取消（abort），则跳过
        if (taskParams._isAborted) {
            _scheduler(); // 递归处理下一个
            return;
        }

        _runningCount++;
        
        // 执行实际请求
        const { type, options, virtualTask, retry } = taskParams;
        const originalMethod = type === 'request' ? _originalRequest : _originalDownload;

        // 包装回调以处理并发计数和错误
        const originalSuccess = options.success;
        const originalFail = options.fail;
        const originalComplete = options.complete;

        const newOptions = Object.assign({}, options, {
            success: (res) => {
                // 拦截 429 错误
                if (res.statusCode === 429 && retry > 0) {
                    console.warn(`[WXGate] 触发429，${RETRY_DELAY}ms后重试... (剩余${retry}次)`);
                    _runningCount--; // 释放资源用于重试（虽然重试本身也要占用）
                    setTimeout(() => {
                        // 重新入队，高优先级插队
                        _queue.unshift({
                            type,
                            options,
                            virtualTask,
                            retry: retry - 1,
                            _isAborted: false
                        });
                        _scheduler();
                    }, RETRY_DELAY);
                    return;
                }
                if (originalSuccess) originalSuccess(res);
            },
            fail: (err) => {
                // 某些真机环境下 429 可能会走 fail 回调
                if (err && (err.errMsg || '').indexOf('429') >= 0 && retry > 0) {
                    console.warn(`[WXGate] 触发429(Fail)，重试...`);
                    _runningCount--;
                    setTimeout(() => {
                        _queue.unshift({
                            type,
                            options,
                            virtualTask,
                            retry: retry - 1,
                            _isAborted: false
                        });
                        _scheduler();
                    }, RETRY_DELAY);
                    return;
                }
                if (originalFail) originalFail(err);
            },
            complete: (res) => {
                // 只有非重试逻辑才减少计数
                if (!(res.statusCode === 429 && retry > 0)) {
                    _runningCount--;
                    _scheduler(); // 触发下一个
                }
                if (originalComplete) originalComplete(res);
            }
        });

        // 发起真实调用
        const realTask = originalMethod.call(wx, newOptions);

        // 桥接 realTask 的方法到 virtualTask
        if (virtualTask && realTask) {
            virtualTask._bridgeTo(realTask);
        }
    }

    /**
     * 虚拟任务类 (用于欺骗Cocos引擎)
     * 必须实现 abort, onProgressUpdate 等接口
     */
    class VirtualTask {
        constructor(queueItem) {
            this._queueItem = queueItem;
            this._realTask = null;
            this._onProgressUpdateCallback = null;
            this._onHeadersReceivedCallback = null;
        }

        _bridgeTo(realTask) {
            this._realTask = realTask;
            // 如果之前注册了回调，现在立即绑定
            if (this._onProgressUpdateCallback) realTask.onProgressUpdate(this._onProgressUpdateCallback);
            if (this._onHeadersReceivedCallback) realTask.onHeadersReceived(this._onHeadersReceivedCallback);
        }

        abort() {
            // 1. 如果还在队列中，标记为取消
            if (this._queueItem) {
                this._queueItem._isAborted = true;
            }
            // 2. 如果已经运行，调用真实的 abort
            if (this._realTask) {
                this._realTask.abort();
            }
        }

        onProgressUpdate(cb) {
            this._onProgressUpdateCallback = cb;
            if (this._realTask) this._realTask.onProgressUpdate(cb);
        }

        onHeadersReceived(cb) {
            this._onHeadersReceivedCallback = cb;
            if (this._realTask) this._realTask.onHeadersReceived(cb);
        }
        
        // 兼容 off 方法
        offProgressUpdate(cb) { if(this._realTask) this._realTask.offProgressUpdate(cb); }
        offHeadersReceived(cb) { if(this._realTask) this._realTask.offHeadersReceived(cb); }
    }

    // ================= 劫持入口 =================

    wx.request = function(options) {
        // 并不是所有 request 都需要队列（比如上报），但为了绝对安全，全部拦截
        // 除非明确标记 ignoreQueue (仅限内部使用)
        if (options.ignoreQueue) {
            return _originalRequest.call(wx, options);
        }

        const queueItem = {
            type: 'request',
            options: options,
            virtualTask: null,
            retry: RETRY_COUNT,
            _isAborted: false
        };

        const task = new VirtualTask(queueItem);
        queueItem.virtualTask = task;

        _queue.push(queueItem);
        _scheduler();

        return task;
    };

    wx.downloadFile = function(options) {
        const queueItem = {
            type: 'download',
            options: options,
            virtualTask: null,
            retry: RETRY_COUNT,
            _isAborted: false
        };

        const task = new VirtualTask(queueItem);
        queueItem.virtualTask = task;

        _queue.push(queueItem);
        _scheduler();

        return task;
    };

    wx.__network_gate_installed__ = true;
    console.log('[WXGate] 全局网络拦截器已激活，并发限制:', MAX_CONCURRENCY);

})();
```

### 3.2 部署方式 (Deployment)

为了保证该代码在Cocos引擎加载前执行，我们需要修改构建模板。

1.  **位置**：在项目根目录创建 `build-templates/wechatgame/game.ejs` (如果不存在，请从构建出的 `wechatgame/game.json/js` 反推，通常 Cocos 3.x 构建生成的是 `game.js`)。
    *   *注意*：Cocos Creator 3.x 的构建模板机制比较复杂，直接修改构建后的 `game.js` 最简单，但为了自动化，建议使用构建插件 (Build Plugin)。
    *   **简易方案**：在 `src` 目录下新建一个 `wx-gate.js`，然后在构建流程中，手动或通过脚本将其内容粘贴到构建输出的 `game.js` 的**第一行**。

2.  **构建钩子脚本** (推荐):
    创建 `tools/inject-gate.js`:
    ```javascript
    const fs = require('fs');
    const path = require('path');

    // 这里的代码即上面的 WXNetworkGate.js 的内容字符串
    const GATE_CODE = `... (将上面的代码压缩成一行或保持原样) ...`;

    exports.onAfterBuild = function(options, result) {
        if (options.platform !== 'wechatgame') return;
        
        const gameJsPath = path.join(result.dest, 'game.js');
        if (fs.existsSync(gameJsPath)) {
            let content = fs.readFileSync(gameJsPath, 'utf-8');
            // 插入到最前面
            content = GATE_CODE + '\n' + content;
            fs.writeFileSync(gameJsPath, content);
            console.log('[BuildHook] WXNetworkGate injected successfully!');
        }
    };
    ```

### 3.3 兼容性与风险规避

1.  **`wx.onPerformanceEntry` 问题**：
    *   该问题通常出现在调用 `wx.getPerformance()` 时。我们的拦截器代码**完全不涉及 Performance API**，因此是安全的。
    *   为了防止引擎内部因为网络行为改变而触发该 bug，确保测试基础库版本 >= 2.11.0。

2.  **Task 对象兼容性**：
    *   我们模拟了 `abort`, `onProgressUpdate`, `onHeadersReceived`。这是 Cocos 引擎下载器主要使用的方法。
    *   如果未来微信增加了新方法，需要同步更新 `VirtualTask`。

3.  **同步性**：
    *   `wx.downloadFile` 本身是同步返回 Task 对象，异步执行网络。我们的 `VirtualTask` 保持了这一行为。

## 四、 预期效果

1.  **并发曲线**：无论 Cocos 发起多少个 Bundle 加载，无论 `maxConcurrency` 设置为 8 还是 20，实际流向微信底层的请求永远是一条平滑的直线（Max 6）。
2.  **429 根治**：因为永远触碰不到 10 的红线，429 将在物理层面上消失。
3.  **自动重试**：即便是网络抖动导致的偶发 429，也会在拦截器内部被静默消化，对上层 Cocos 引擎透明。

## 五、 总结

方案 013 试图通过"行政命令"（Config）来管理交通，但底层驱动（Adapter）置若罔闻。
方案 014 则是直接**接管交通信号灯**。

这是解决 429 问题的**终局之战**。
