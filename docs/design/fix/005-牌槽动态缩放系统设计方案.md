# 005 - 牌槽动态缩放系统设计方案

## 文档信息

- **创建日期**: 2025-10-19
- **问题来源**: 用户反馈牌槽扩容后超出屏幕宽度
- **影响范围**: 牌槽UI布局、字母卡片缩放、扩容动画系统
- **优先级**: 🟡 **P1（影响游戏体验，但不阻塞核心功能）**
- **方案类型**: 纯设计方案（不包含代码实现）

---

## 问题背景与现状分析

### 1. 问题描述

#### 用户反馈
> "下方牌槽的自动扩展，初始7个牌槽，在满足一定条件后开始增加，但是现在牌槽的大小7个正好就占满了屏幕的宽度，导致后面新增的牌槽已经超出了屏幕范围。"

#### 核心矛盾
- **设计需求**：牌槽需要从初始7格扩展到最大10格（或12格）
- **UI限制**：7格已占满750px宽度的约91%（680px可用区域）
- **扩容困境**：继续增加格子会超出屏幕边界，导致格子不可见或布局异常

### 2. 当前技术现状分析

#### 2.1 牌槽布局系统（基于 SlotQueue.ts 代码分析）

**关键代码位置**：[SlotQueue.ts:121-137](src/cocos/assets/scripts/ui/SlotQueue.ts#L121-L137)

```typescript
private layoutSlotsWithPureMath(): void {
    const slotWidth = 90; // 卡片标准宽度（固定值）
    // 不添加间距，完全紧密排列
    const totalWidth = slotWidth * this.slotNodes.length;
    const startX = -totalWidth / 2 + slotWidth / 2;

    for (let i = 0; i < this.slotNodes.length; i++) {
        const slotNode = this.slotNodes[i];
        if (!slotNode) continue;

        // 纯数学计算位置（相对于container）
        const x = startX + i * slotWidth;
        slotNode.setPosition(x, 0, 0);
    }
}
```

**当前布局特点**：
- ✅ **优点**：纯数学定位，精准可控，无Layout组件干扰
- ✅ **优点**：紧密排列（无间距），最大化利用空间
- ❌ **限制**：`slotWidth = 90px` 是硬编码的固定值
- ❌ **问题**：当 `slotNodes.length` 增加时，`totalWidth` 线性增长，无法自适应屏幕宽度

**7格布局计算**：
```
slotWidth = 90px
totalWidth = 90 × 7 = 630px
startX = -630/2 + 90/2 = -270px
各格子位置：
  slot[0]: x = -270 + 0×90 = -270px
  slot[1]: x = -270 + 1×90 = -180px
  slot[2]: x = -270 + 2×90 = -90px
  slot[3]: x = -270 + 3×90 = 0px（中心）
  slot[4]: x = -270 + 4×90 = 90px
  slot[5]: x = -270 + 5×90 = 180px
  slot[6]: x = -270 + 6×90 = 270px
```

**屏幕适配参数**：
- **设计分辨率**：750×1334（竖屏）
- **适配模式**：Fit Height
- **可用宽度**：约680px（假设左右各留35px边距）
- **7格占用**：630px（占可用宽度的92.6%）

**10格布局计算（如果不做动态缩放）**：
```
totalWidth = 90 × 10 = 900px
startX = -900/2 + 90/2 = -405px
各格子位置：
  slot[0]: x = -405px ❌ 超出屏幕左边界（-375px）
  ...
  slot[9]: x = 405px ❌ 超出屏幕右边界（+375px）
```

**结论**：不做动态缩放的情况下，10格会超出屏幕约30px（每侧15px），导致边缘格子部分不可见。

#### 2.2 扩容系统（基于 SlotQueue.ts 代码分析）

**关键代码位置**：[SlotQueue.ts:450-471](src/cocos/assets/scripts/ui/SlotQueue.ts#L450-L471)

```typescript
private checkExpand(): void {
    // 扩容逻辑由SlotQueueManager内部处理
    const newCapacity = this.slotManager.getState().capacity;

    // 如果容量增加，需要添加新的slot节点并重新布局
    if (newCapacity > this.slotNodes.length) {
        console.log(`[SlotQueue] 需要扩容：从 ${this.slotNodes.length} -> ${newCapacity}`);

        // 添加新slot节点
        for (let i = this.slotNodes.length; i < newCapacity; i++) {
            const slotNode = this.createEmptySlotNode();
            this.slotNodes.push(slotNode);
        }

        // 重新应用纯数学定位
        this.layoutSlotsWithPureMath();
        console.log(`[SlotQueue] 扩容完成，现有 ${this.slotNodes.length} 个slot节点`);
    }

    // UI动画反馈
    this.playExpandAnimation();
}

private playExpandAnimation(): void {
    if (!this.slotItemsContainer) return;

    tween(this.slotItemsContainer)
        .to(0.2, { scale: new Vec3(1.1, 1.1, 1) })
        .to(0.2, { scale: new Vec3(1, 1, 1) })
        .start();
}
```

**扩容流程分析**：
1. SlotQueueManager 检测扩容条件（如消除3个单词）
2. `checkExpand()` 检测到 `newCapacity > slotNodes.length`
3. 创建新的 slot 节点并添加到数组
4. 调用 `layoutSlotsWithPureMath()` 重新计算所有格子位置
5. 播放整体缩放动画（container 放大1.1倍再恢复）

**当前扩容动画问题**：
- ❌ **问题1**：仅缩放 container 整体，没有单个格子的缩小动画
- ❌ **问题2**：格子宽度仍为固定90px，无法适应新容量
- ❌ **问题3**：没有视觉上的"格子缩小"反馈，玩家不明显感知到容量变化

```typescript
public addLetter(letter: string, tileNode?: Node): void {
    if (this.slotManager.isFull()) {
        console.warn('牌槽已满，无法添加字母');
        this.node.emit('slot-full');
        return;
    }

    this.slotManager.addLetter(letter);

    if (tileNode && tileNode.isValid) {
        const letters = this.slotManager.getLetters();
        const slotIndex = letters.length - 1; // 刚添加的字母对应的slot索引
        const targetSlot = this.slotNodes[slotIndex];

        if (targetSlot && targetSlot.isValid) {
            // 将字母牌移动到slot节点下
            tileNode.setParent(targetSlot);
            tileNode.setPosition(0, 0, 0); // 重置为slot的中心
            tileNode.setScale(1, 1, 1); // ⚠️ 重置缩放为1（问题所在！）

            // 设置为高亮状态
            const tile = tileNode.getComponent(LetterTile);
            if (tile) {
                tile.setState('highlight');
            }

            console.log(`[SlotQueue] 字母牌已移动到slot[${slotIndex}]`);
        }
    }
}
```

**字母卡片缩放问题**：
- ❌ **问题1**：`removeCard()` 飞行时缩放到 0.8 倍
- ❌ **问题2**：`addLetter()` 将字母重置为 1.0 倍
- ❌ **结论**：**字母卡片的缩放不会跟随牌槽的动态缩放！**

**需要同步缩放的逻辑**：
1. 飞行动画的目标缩放应为 **当前牌槽的缩放比例**
2. `addLetter()` 中的 `setScale(1, 1, 1)` 应改为 **当前牌槽的缩放比例**
3. 已在牌槽中的字母卡片，扩容时需要**同步缩小**

### 3. 容量上限对比分析（10格 vs 12格）

#### 3.1 UI显示效果对比

假设槽位区域可用宽度为 **680px**（左右各留35px边距），槽位间距为 **0px**（紧密排列）：

|------|------------|-------------------|------------|
| **7格** | 97.1px | 100% | ⭐⭐⭐⭐⭐ 宽敞舒适（初始状态） |
| **8格** | 85.0px | 87.5% | ⭐⭐⭐⭐ 略微紧凑，可接受 |

## 动态缩放方案设计

### 1. 核心设计思路

#### 1.1 方案概述

**目标**：实现牌槽从7格平滑扩展到10格，同时保证所有格子始终完整显示在屏幕内。

**核心策略**：**分段式动态缩放**
- **阶段1（7格）**：初始状态，100%缩放，格子宽度约97px
- **阶段2（8格）**：第一次扩容，87.5%缩放，格子宽度约85px
- **阶段3（9-10格）**：后续扩容，71%缩放，格子宽度约68px

**设计原则**：
1. **渐进式缩放**：避免一次性剧烈缩小，分3个档位逐步调整
2. **视觉稳定性**：9-10格使用同一缩放比例，避免频繁变化
3. **字母同步缩放**：牌槽缩放时，字母卡片同步缩放
4. **动画反馈**：扩容时播放"闪烁缩小"动画，让玩家感知变化

---

#### 1.2 缩放档位设计（三档式）

**档位表**：

| 当前容量 | 缩放比例 | 单个槽位宽度（理论） | 总宽度（7格基准） | 字母字体大小（估算） |
|---------|---------|---------------------|------------------|---------------------|
| **7格** | 100% (1.0) | 97.1px | 680px | 36px |
| **8格** | 87.5% (0.875) | 85.0px | 680px | 31.5px |
| **9格** | 71% (0.71) | 68.9px | 620px | 25.6px |
| **10格** | 71% (0.71) | 68.0px | 680px | 25.2px |

**计算公式**：

```typescript
/**
 * 根据当前容量计算槽位缩放比例
 * @param capacity 当前容量（7-10）
 * @returns 缩放比例（1.0 / 0.875 / 0.71）
 */
function getSlotScale(capacity: number): number {
    if (capacity <= 7) {
        return 1.0;    // 100%（初始状态）
    } else if (capacity === 8) {
        return 0.875;  // 87.5%（第一次扩容）
    } else {
        return 0.71;   // 71%（9-10格，统一缩放）
    }
}
```

**为什么选择这些缩放比例？**

1. **100%（7格）**：
   - 初始状态，无需缩放
   - 格子宽度最大化，字母最清晰
   - 总宽度680px，占屏幕91%

2. **87.5%（8格）**：
   - 第一次扩容，缩小幅度温和（仅-12.5%）
   - 玩家视觉上不会感到突兀
   - 格子宽度85px，字母字体31.5px，依然清晰
   - 计算公式：`7/8 = 0.875`

3. **71%（9-10格）**：
   - 后续扩容，统一使用同一缩放比例
   - 避免9格→10格时再次缩放，保持视觉稳定性
   - 格子宽度68px，字母字体25px，接近但未达到可读性下限
   - 计算公式：约 `7/10 = 0.70`（取71%稍留余量）

**视觉效果对比**：

### 2. 布局计算逻辑重构

#### 2.1 当前布局逻辑的问题

**现状（SlotQueue.ts:121-137）**：

**问题**：
- `slotWidth = 90` 是硬编码的固定值
- 扩容时，`totalWidth` 线性增长，导致超出屏幕
- 无法适应动态缩放需求

#### 2.2 重构后的布局逻辑（设计方案）

**新布局逻辑**：

```typescript
/**
 * 使用纯数学定位算法排列slot节点（支持动态缩放）
 * ✅ 新增：根据当前容量动态计算slot宽度
 */
private layoutSlotsWithPureMath(): void {
    const capacity = this.slotNodes.length;
    const scale = this.getSlotScale(capacity);

    // ✅ 动态计算slot宽度
    const baseSlotWidth = 97; // 7格时的基准宽度（680/7 ≈ 97px）
    const slotWidth = baseSlotWidth * scale;

    const totalWidth = slotWidth * capacity;
    const startX = -totalWidth / 2 + slotWidth / 2;

    for (let i = 0; i < this.slotNodes.length; i++) {
        const slotNode = this.slotNodes[i];
        if (!slotNode) continue;

        // 计算位置
        const x = startX + i * slotWidth;
        slotNode.setPosition(x, 0, 0);

        // ✅ 设置slot节点的缩放
        slotNode.setScale(scale, scale, 1);

        console.log(`[SlotQueue] slot[${i}] 位置: (${x.toFixed(2)}, 0), 缩放: ${scale}`);
    }
}

/**
 * ✅ 新增：根据容量获取缩放比例
 */
```

### 3. 字母卡片同步缩放机制

#### 3.1 问题分析

**当前字母卡片的生命周期**：
1. **阶段1（牌堆）**：字母卡片在 `StackBoard` 中，scale = 1.0
2. **阶段2（飞行）**：`removeCard()` 触发飞行动画，scale = 0.8
3. **阶段3（槽位）**：`addLetter()` 将卡片 `setParent` 到 slot 下，scale = 1.0
4. **阶段4（槽位中）**：卡片停留在槽位中，scale = 1.0

**问题**：
- ❌ 阶段3：`setScale(1, 1, 1)` 硬编码为1.0，无法适应动态缩放
- ❌ 阶段4：扩容时，已在槽位的卡片不会同步缩小
- ❌ 阶段2：飞行目标缩放应为当前槽位的缩放比例，而非固定0.8

#### 3.2 同步缩放方案（设计）

### 4. 扩容动画设计

#### 4.1 用户需求回顾

> "简单做一个缩小的动画，就是原尺寸和缩小后尺寸一闪一闪的那种效果，最后固定成缩小后的尺寸。"

**需求拆解**：
1. **闪烁效果**：原尺寸 ↔ 缩小后尺寸，循环2-3次
2. **最终状态**：动画结束后，固定为缩小后的尺寸
3. **触发时机**：每次扩容时播放（7→8格、8→9格、9→10格）

---

#### 4.2 动画设计方案

**动画流程**：
```
扩容触发
  ↓
播放闪烁动画（原尺寸 ↔ 新尺寸，循环3次）
  ↓
固定为新尺寸
  ↓
通知StackBoard更新飞行目标缩放
```

**动画实现（伪代码）**：

```typescript
/**
 * 播放扩容动画（闪烁缩小效果）
 * @param oldScale 原缩放比例
 * @param newScale 新缩放比例
 */
private playExpandAnimation(oldScale: number, newScale: number): void {
    if (!this.slotItemsContainer) return;

    console.log(`[SlotQueue] 播放扩容动画：${oldScale} → ${newScale}`);

    // 停止之前的扩容动画（如果有）
    Tween.stopAllByTag(2001, this.slotItemsContainer);

    // 闪烁动画：原尺寸 ↔ 新尺寸，循环3次
    tween(this.slotItemsContainer)
        .tag(2001) // 标记为扩容动画
        // 第1次闪烁
        .to(0.15, { scale: new Vec3(oldScale, oldScale, 1) }, { easing: 'sineInOut' })
        .to(0.15, { scale: new Vec3(newScale, newScale, 1) }, { easing: 'sineInOut' })
        // 第2次闪烁
        .to(0.15, { scale: new Vec3(oldScale, oldScale, 1) }, { easing: 'sineInOut' })
        .to(0.15, { scale: new Vec3(newScale, newScale, 1) }, { easing: 'sineInOut' })
        // 第3次闪烁
        .to(0.15, { scale: new Vec3(oldScale, oldScale, 1) }, { easing: 'sineInOut' })
        .to(0.15, { scale: new Vec3(newScale, newScale, 1) }, { easing: 'sineInOut' })
        .call(() => {
            // 确保最终固定为新尺寸
            this.slotItemsContainer.setScale(newScale, newScale, 1);
            console.log(`[SlotQueue] 扩容动画完成，固定为缩放比例：${newScale}`);

            // 触发事件，通知其他组件更新
            this.node.emit('capacity-expanded', newScale);
        })
        .start();
}
```

**动画参数说明**：
- **缓动函数**：`sineInOut`（平滑过渡）
- **单次闪烁时长**：0.15秒 × 2 = 0.3秒
- **总时长**：0.3秒 × 3次 = 0.9秒
- **Tag标记**：`2001`（便于停止动画）

**视觉效果**：
```
时间轴：
0.00s: oldScale (原尺寸)
0.15s: newScale (新尺寸)
0.30s: oldScale (原尺寸)
0.45s: newScale (新尺寸)
0.60s: oldScale (原尺寸)
0.75s: newScale (新尺寸)
0.90s: 固定为newScale
```

**注意事项**：
1. **动画作用对象**：`slotItemsContainer`（slot节点的容器）
2. **为什么不对单个slot节点播放动画？**
   - 单个slot节点的scale已用于控制缩放比例
   - 如果再播放动画，会导致scale值混乱
   - 对container播放动画，所有子节点（slot）会同步闪烁
3. **如何避免动画重叠？**
   - 使用 `Tween.stopAllByTag(2001)` 停止之前的动画
   - 确保同一时间只有一个扩容动画在播放

---

#### 4.3 动画与缩放的协调

**问题**：如果 `slotItemsContainer` 播放缩放动画，而 `slotNode` 也设置了缩放，会不会冲突？

**答案**：不会冲突，因为：
- `slotNode.setScale(scale)` 设置的是 **localScale**（相对于父节点）
- `slotItemsContainer.scale` 播放动画，所有子节点会 **继承worldScale**
- 最终 `slotNode` 的 `worldScale = slotNode.localScale × slotItemsContainer.scale`

**举例**：
```
假设：
- slotNode.localScale = 0.71（9-10格的缩放）
- slotItemsContainer.scale = 1.0（动画开始前）

播放动画时：
- slotItemsContainer.scale 从 1.0 → 0.71（闪烁）
- slotNode.worldScale = 0.71 × 0.71 = 0.504（过度缩小）

❌ 问题：会导致slot节点在动画期间被双重缩放！
```

**修正方案**：
- **方案A**：动画期间，`slotNode.localScale` 保持为1.0，仅在动画结束后设置为新缩放
- **方案B**：动画不对 `slotItemsContainer` 播放，而是对每个 `slotNode` 播放

**推荐方案A**：

```typescript
private playExpandAnimation(oldScale: number, newScale: number): void {
    // 1. 先将所有slot节点的localScale重置为1.0
    for (const slotNode of this.slotNodes) {
        slotNode.setScale(1, 1, 1);
    }

    // 2. 对container播放闪烁动画
    tween(this.slotItemsContainer)
        .tag(2001)
        // 闪烁效果...
        .call(() => {
            // 3. 动画结束后，恢复container的scale为1.0
            this.slotItemsContainer.setScale(1, 1, 1);

            // 4. 为每个slot节点设置新缩放
            for (const slotNode of this.slotNodes) {
                slotNode.setScale(newScale, newScale, 1);
            }

            console.log(`[SlotQueue] 扩容动画完成，固定为缩放比例：${newScale}`);
        })
        .start();
}
```

**流程说明**：
1. **动画前**：将所有slot的localScale重置为1.0
2. **动画中**：container的scale闪烁（oldScale ↔ newScale）
3. **动画后**：container的scale恢复为1.0，slot的localScale设置为newScale

**优势**：
- ✅ 动画流畅，视觉效果清晰
- ✅ 避免双重缩放问题
- ✅ 动画结束后，slot节点的scale与预期一致

```typescript
    AudioMgr.playSound('slot_expand');
```

## 总结

### 方案核心要点

1. **分段式缩放**：7格（100%）→ 8格（87.5%）→ 9-10格（71%），3个档位
2. **字母同步缩放**：字母卡片跟随slot节点缩放，继承worldScale
3. **扩容动画**：原尺寸 ↔ 新尺寸闪烁3次，总时长0.9秒
4. **最大容量**：10格（配合救济机制，实际可达12格）

### A.1 SlotQueue.ts 核心方法

```typescript
// 缩放计算
private getSlotScale(capacity: number): number {
    if (capacity <= 7) return 1.0;
    else if (capacity === 8) return 0.875;
    else return 0.71;
}

// 布局逻辑
private layoutSlotsWithPureMath(): void {
    const capacity = this.slotNodes.length;
    const scale = this.getSlotScale(capacity);
    const baseSlotWidth = 97;
    const slotWidth = baseSlotWidth * scale;
    const totalWidth = slotWidth * capacity;
    const startX = -totalWidth / 2 + slotWidth / 2;

    for (let i = 0; i < this.slotNodes.length; i++) {
        const slotNode = this.slotNodes[i];
        const x = startX + i * slotWidth;
        slotNode.setPosition(x, 0, 0);
        slotNode.setScale(scale, scale, 1);
    }
}

// 扩容动画
private playExpandAnimation(oldScale: number, newScale: number): void {
    for (const slotNode of this.slotNodes) {
        slotNode.setScale(1, 1, 1);
    }

    tween(this.slotItemsContainer)
        .tag(2001)
        .to(0.15, { scale: new Vec3(oldScale, oldScale, 1) })
        .to(0.15, { scale: new Vec3(newScale, newScale, 1) })
        .to(0.15, { scale: new Vec3(oldScale, oldScale, 1) })
        .to(0.15, { scale: new Vec3(newScale, newScale, 1) })
        .to(0.15, { scale: new Vec3(oldScale, oldScale, 1) })
        .to(0.15, { scale: new Vec3(newScale, newScale, 1) })
        .call(() => {
            this.slotItemsContainer.setScale(1, 1, 1);
            for (const slotNode of this.slotNodes) {
                slotNode.setScale(newScale, newScale, 1);
            }
        })
        .start();
}
```
