## 一、 问题复盘与诊断

根据最新的真机调试截图，我们发现了方案 014 实施后的五个核心残留问题。这些问题并非方案架构错误，而是**边界情况处理不严谨**和**引擎/微信兼容性细节**导致的。

### 1.1 诊断分析

1.  **`ERR_CONNECTION_CLOSED` 与 429 依然存在**
    *   **现象**：拦截器虽然工作并触发了重试日志，但请求依然失败，且出现了连接关闭错误。
    *   **原因**：
        *   **并发数 6 依然过高**：对于某些弱网或服务器配置严格的环境，6 个 TCP 连接可能触发服务器侧的防火墙（非微信侧限制）。
        *   **网络抖动**：`ERR_CONNECTION_CLOSED` 通常是网络波动或服务器主动断开。拦截器目前的重试逻辑主要针对 429，可能没有很好地覆盖这种网络层错误。
    *   **对策**：将并发降至 **4**（黄金安全值），并将网络错误纳入自动重试范畴。

2.  **`wx.onPerformanceEntry undefined`**
    *   **现象**：游戏崩溃，报错 `TypeError: undefined is not a function`。
    *   **原因**：这是一个经典的 **Cocos Creator 3.x + 微信小游戏兼容性 Bug**。Cocos 引擎尝试调用微信的性能监控 API，但某些基础库版本下该 API 未定义或行为不一致。
    *   **对策**：在 `WXNetworkGate` 中直接 Polyfill（补丁）该方法，防止引擎报错。

3.  **Loading 场景卡死在 100%**
    *   **现象**：进度条满了但无法跳转，或者跳转后背景图缺失。
    *   **原因**：当 `PreloadManager` 等待的资源（如背景图）因为 `ERR_CONNECTION_CLOSED` 最终失败时，如果 `Promise.all` 没有正确处理 `catch`，整个流程就会挂起（Pending 状态）。
    *   **对策**：在 `PreloadManager` 中增加**容错机制**，资源加载失败视为"完成"（但标记错误），确保流程能继续走下去。

4.  **进度条"倒车"（Moonwalking）**
    *   **现象**：进度从 50% 变回 10%，再变回 60%。
    *   **原因**：`PreloadManager` 在加载不同的 Bundle 组时，可能重置了局部进度变量，导致计算出的全局进度忽大忽小。
    *   **对策**：在 UI 层或 Manager 层实现**单调递增**逻辑，`current = Math.max(current, last)`。

5.  **日志啰嗦**
    *   **现象**：显示具体文件名，不仅丑陋而且让用户感到困惑。
    *   **对策**：UI 层强制拦截文本，只显示"资源加载中..."。

### 2.1 修正 `WXNetworkGate.js` (注入脚本)

**位置**：`build-templates/wechatgame/game.ejs` 或通过构建工具注入到 `game.js` 头部。

**主要改进**：
1.  增加 `wx.onPerformanceEntry` Polyfill。
2.  并发数降为 **4**。
3.  增加对 `ERR_CONNECTION_CLOSED` 等网络错误的重试支持。
4.  优化重试逻辑，防止重试任务被丢弃。

```javascript
/**
 * WXNetworkGate.js v1.1
 * 究极429解决方案修正版
 */

(function() {
    if (typeof wx === 'undefined') return;
    
    // ----------------------------------------------------------------
    // Fix 1: Polyfill wx.onPerformanceEntry to prevent engine crash
    // ----------------------------------------------------------------
    if (!wx.onPerformanceEntry) {
        console.log('[WXGate] Polyfill wx.onPerformanceEntry');
        wx.onPerformanceEntry = function() {};
    }
    // Prevent multiple injections
    if (wx.__network_gate_installed__) return;

    console.log('[WXGate] 初始化全局网络拦截器 v1.1...');

    // ================= 配置区 =================
    // Fix 2: Lower concurrency from 6 to 4 for absolute safety
    const MAX_CONCURRENCY = 4; 
    const RETRY_COUNT = 3;     
    const RETRY_DELAY = 1000;  
    // =========================================

    const _originalRequest = wx.request;
    const _originalDownload = wx.downloadFile;

    let _runningCount = 0;
    const _queue = [];

    function _scheduler() {
        if (_runningCount >= MAX_CONCURRENCY) return;
        if (_queue.length === 0) return;

        const taskParams = _queue.shift();
        if (taskParams._isAborted) {
            _scheduler();
            return;
        }

        _runningCount++;
        
        const { type, options, virtualTask, retry } = taskParams;
        const originalMethod = type === 'request' ? _originalRequest : _originalDownload;

        const originalSuccess = options.success;
        const originalFail = options.fail;
        const originalComplete = options.complete;

        // Fix 3: Enhanced Error Handling & Retry Logic
        const handleRetry = (reason, resOrErr) => {
            if (retry > 0) {
                const delay = RETRY_DELAY + Math.random() * 500; // Add jitter
                console.warn(`[WXGate] ${reason}, ${Math.floor(delay)}ms后重试... (剩余${retry}次) URL: ${options.url}`);
                
                // Critical: Decrement count immediately so we don't block while waiting
                _runningCount--; 
                
                setTimeout(() => {
                    _queue.unshift({
                        type,
                        options,
                        virtualTask,
                        retry: retry - 1,
                        _isAborted: false
                    });
                    _scheduler();
                }, delay);
                return true; // Retrying
            }
            return false; // No more retries
        };

        const newOptions = Object.assign({}, options, {
            success: (res) => {
                // Handle 429 strictly
                if (res.statusCode === 429) {
                    if (handleRetry('触发429', res)) return;
                }
                // Handle 5xx Server Errors (Optional, but good for stability)
                if (res.statusCode >= 500 && res.statusCode < 600) {
                    if (handleRetry(`服务器错误${res.statusCode}`, res)) return;
                }
                
                if (originalSuccess) originalSuccess(res);
            },
            fail: (err) => {
                const errMsg = err ? (err.errMsg || err.message || '') : '';
                
                // Handle Network Errors (Connection closed, timeout, etc.)
                // Fix 1 recurrence: ERR_CONNECTION_CLOSED
                if (
                    errMsg.indexOf('429') >= 0 || 
                    errMsg.indexOf('CONNECTION_CLOSED') >= 0 ||
                    errMsg.indexOf('timeout') >= 0 ||
                    errMsg.indexOf('fail') >= 0 // Generic fail often means network issue
                ) {
                    if (handleRetry(`网络错误(${errMsg})`, err)) return;
                }
                
                if (originalFail) originalFail(err);
            },
            complete: (res) => {
                // Only decrement if we are NOT retrying (retrying logic handles decrement itself)
                // We check this by inferring if success/fail handled it. 
                // Actually, safer way: handleRetry returns true, we skip decrement here? 
                // No, handleRetry already decremented. 
                // BUT, wait: if success calls handleRetry, it decrements. 
                // originalComplete should be called ONLY if we are finished (success/fail exhausted).
                // 
                // To simplify: We only call originalComplete if we are NOT retrying.
                // And we only decrement here if we are NOT retrying.
                
                const is429 = (res.statusCode === 429);
                const isNetErr = res.errMsg && (res.errMsg.indexOf('429') >= 0 || res.errMsg.indexOf('CONNECTION_CLOSED') >= 0);
                
                if ((is429 || isNetErr) && retry > 0) {
                    // Retrying, do nothing here (handleRetry did the work)
                } else {
                    _runningCount--;
                    _scheduler();
                    if (originalComplete) originalComplete(res);
                }
            }
        });

        const realTask = originalMethod.call(wx, newOptions);

        if (virtualTask && realTask) {
            virtualTask._bridgeTo(realTask);
        }
    }

    class VirtualTask {
        constructor(queueItem) {
            this._queueItem = queueItem;
            this._realTask = null;
            this._cbs = { progress: null, headers: null };
        }

        _bridgeTo(realTask) {
            this._realTask = realTask;
            if (this._cbs.progress) realTask.onProgressUpdate(this._cbs.progress);
            if (this._cbs.headers) realTask.onHeadersReceived(this._cbs.headers);
        }

        abort() {
            if (this._queueItem) this._queueItem._isAborted = true;
            if (this._realTask) this._realTask.abort();
        }

        onProgressUpdate(cb) { 
            this._cbs.progress = cb; 
            if (this._realTask) this._realTask.onProgressUpdate(cb); 
        }
        onHeadersReceived(cb) { 
            this._cbs.headers = cb; 
            if (this._realTask) this._realTask.onHeadersReceived(cb); 
        }
        offProgressUpdate(cb) { if(this._realTask) this._realTask.offProgressUpdate(cb); }
        offHeadersReceived(cb) { if(this._realTask) this._realTask.offHeadersReceived(cb); }
    }

    wx.request = function(options) {
        if (options.ignoreQueue) return _originalRequest.call(wx, options);
        const qItem = { type: 'request', options, virtualTask: null, retry: RETRY_COUNT, _isAborted: false };
        const task = new VirtualTask(qItem);
        qItem.virtualTask = task;
        _queue.push(qItem);
        _scheduler();
        return task;
    };

    wx.downloadFile = function(options) {
        const qItem = { type: 'download', options, virtualTask: null, retry: RETRY_COUNT, _isAborted: false };
        const task = new VirtualTask(qItem);
        qItem.virtualTask = task;
        _queue.push(qItem);
        _scheduler();
        return task;
    };

    wx.__network_gate_installed__ = true;
    console.log('[WXGate] 全局网络拦截器已激活 v1.1, 并发限制:', MAX_CONCURRENCY);
})();
```

### 2.2 修正 `LoadingUI.ts` (体验优化)

**文件**: `src/cocos/assets/scripts/ui/LoadingUI.ts`

**主要改进**：
1.  强制锁定文本，不显示文件名。
2.  实现进度条"单调递增"，防止倒车。

```typescript
// 在 LoadingUI 类中修改/添加

private _lastProgress: number = 0;

/**
 * 更新进度
 * @param progress 0-1
 * @param message (已废弃，忽略)
 */
public updateProgress(progress: number, message: string): void {
    // Fix 4: 防止进度条倒车
    if (progress < this._lastProgress) {
        // 如果新进度比旧进度小，忽略（或者平滑处理）
        // 但为了防止死锁，如果 progress 经常跳变，我们取最大值
        progress = this._lastProgress;
    } else {
        this._lastProgress = progress;
    }

    // Fix 5: 强制隐藏文件名，只显示统一文案
    const cleanMessage = "资源加载中..."; 

    if (this.progressBar && this.progressBar.node && this.progressBar.node.isValid) {
        // 使用 tween 平滑过渡
        tween(this.progressBar)
            .to(0.2, { progress: progress })
            .start();
    }

    if (this.progressLabel) {
        this.progressLabel.string = `${Math.round(progress * 100)}%`;
    }

    if (this.statusLabel) {
        this.statusLabel.string = cleanMessage;
    }
}
```

### 2.3 修正 `PreloadManager.ts` (逻辑容错)

**文件**: `src/cocos/assets/scripts/app/PreloadManager.ts`

**主要改进**：
1.  `ensureBundleLoaded` 和 `preloadCriticalAssets` 增加 `catch` 块，防止单个资源失败导致整个 Promise 链挂起。
2.  移除会将文件名传给 UI 的逻辑（虽然 UI 层已经拦截，但源头清理更好）。

```typescript
// 修改 ensureBundleLoaded
public async ensureBundleLoaded(bundleName: string): Promise<assetManager.Bundle | null> {
    // ... 前面的缓存检查逻辑 ...

    try {
        // ... loadBundleInternal 调用 ...
        const bundle = await this.loadBundleInternal(bundleName);
        // ... 缓存逻辑 ...
        return bundle;
    } catch (error) {
        // Fix 3: 容错处理
        // 如果加载失败（即使重试后），记录错误但不抛出，或者返回 null
        // 这样 Loading 场景可以继续往下走（虽然可能缺资源，但比卡死好）
        console.error(`[PreloadManager] Bundle ${bundleName} 最终加载失败，跳过`, error);
        return null; // 返回 null 表示失败但已处理
    }
}

// 修改 preloadAsset
private async preloadAsset(bundle: assetManager.Bundle, bundleName: string, assetPath: string): Promise<void> {
    // ... 
    return new Promise((resolve) => { // 注意这里不 reject
        bundle.load(assetPath, assetType, (err, asset) => {
            if (err) {
                // Fix 3: 资源预热失败仅警告，不阻塞流程
                console.warn(`[PreloadManager] 资源预热失败 ${bundleName}:${assetPath}, 跳过`);
                resolve(); // 依然 resolve，保证 Promise.all 能完成
                return;
            }
            // ... 成功逻辑 ...
            resolve();
        });
    });
}
```

## 四、 总结

这次修正主要解决了**底层兼容性**（Polyfill）、**网络稳定性**（降并发+增强重试）和**用户体验**（进度条逻辑）问题。

这套方案（v1.1）是目前针对微信小游戏环境最稳健的防御体系。它不再假设网络是完美的，而是假设网络随时会挂，并为此做好了兜底准备。
